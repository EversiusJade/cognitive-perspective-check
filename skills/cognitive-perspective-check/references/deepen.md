# Deepen only the selected scope

Read this only after the user selects or explicitly requests deeper work. Continue from the background, core decision, competing perspectives, and conditional judgment already established. Choose the relevant branch; do not run all branches. Briefly state the selected question, assumptions, coverage, and the stopping point. Existing authorization persists; do not re-ask permission for the same analysis.

## Evidence check

Use when a factual unknown could reverse the recommendation. Name the claim, the observation that would support or weaken it, and the smallest affordable check. Use the user's available evidence first. If current external facts are pivotal, retrieve appropriate sources rather than filling gaps with speculation. Report the observation and its limits, then update the recommendation. If evidence cannot be obtained, provide a concrete check the user can run and keep the conclusion conditional; never report an unperformed check as completed.

## Route comparison

Use when the user is choosing between viable approaches. Compare only criteria that change this user's decision, often two or three. Preserve real constraints and the strongest case for each path. Check that the comparison includes meaningful differences in assumptions or priorities, rather than just elaborating your preferred view. Where relevant, identify whose benefits and costs differ. Explain which priority or fact favors each choice. Do not invent weights or scores without a basis. End with one conditional preference and the next reversible action.

## Bounded simulation

Use when the user wants to understand how a selected path unfolds. A simulation is a hypothetical consequence map, not evidence or a probability estimate.

1. State the scenario, objective, constraints, and assumptions.
2. Trace up to three pivotal events or decisions, explaining each causal link.
3. Show one plausible failure route that could change the choice and an observable early signal.
4. Describe what the path gains, costs, and leaves uncertain, including who bears a consequential cost when relevant. Say how the hypothetical result would change the recommendation and suggest one cheap real-world check. Do not treat the simulated result as an observed outcome.

Use qualitative consequences unless inputs justify numbers. Do not invent market demand, precise costs, probabilities, or user reactions. Add further scenarios only when the user chooses them.

## Execution handoff

Use when the user wants to start acting on the selected path. Supply the chosen outcome, success criterion, hard constraints, unresolved pivotal assumption, first action, and condition for revising the plan. Keep the plan proportional to the request; do not regenerate discarded branches. Follow the next task's existing tools, skills, and authorization requirements.

## New information

Maintain a compact working record from the conversation: agreed outcome, relevant rules, selected perspective, hard constraints, pivotal unknown, current branch. Use existing context; persistent storage is not required. When corrected, revise the affected conclusion and briefly explain the change. Reopen the choice only if the correction matters. A user preference selects priorities; it does not establish disputed facts. Your conditional recommendation is also revisable; avoid defending it after its premise changes.
