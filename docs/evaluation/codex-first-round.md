## 采集前登记

使用[预登记模板](../../evals/experiment/preregistration-template.json)登记以下内容，保存为独立的执行批次文件：

- 客户端与确切模型标识、推理设置、工具权限、系统指令和其他技能清单。本机配置当前为 `gpt-6-luna`、`medium`；这是读取的设置，尚不是模型服务返回的版本确认。不可见参数及别名解析记为未知。
- C0 / Cs 的目录发现和正文读取隔离证据；C1 / C2 使用完全相同的技能文件。不要在“无 skill”组发送关闭技能、禁止使用本项目等提示来代替环境隔离。
- 两位独立人工评审的代号、校准记录、随机顺序及时间/调用预算。不能以两次 AI 打分冒充双人评分，作者不是唯一裁决者。
- 输入、量表、协议和目标文件的哈希。发现预检不计入 48 个 pilot 槽位，也不从中挑选“更好”的输入或评分标准。

缺少这些条件时可以收集明确标为“使用走查”的记录，但不能报告无 skill 的因果增益、自然调用率或正式 pilot 完成。

### 文件隔离需要核对的通道

本机除安装目录外，还有源码和 ZIP 副本；公开 GitHub 也能提供正文。所有条件应使用一致的有限工具环境，阻止读取评估材料和其他副本，并控制网络搜索、MCP 和连接器获取通道。当前另外发现 65 个技能条目；应统一冻结或禁用未参与研究的规则，记录最终环境。关闭发现与开启发现组必须重新核对。

[官方权限配置](https://learn.chatgpt.com/docs/permissions)支持命名权限配置和路径禁读，但沙箱权限主要约束本地命令，不能代替其他工具的控制。[Windows 沙箱说明](https://learn.chatgpt.com/docs/windows/windows-sandbox)区分支持禁读的执行方式。权限配置与实际执行都需验证；后续 MXC 预检已观察到目标路径条件性可读、源码副本禁读，且已发现的 MCP 和插件被显式关闭；证据见首批报告。

## 日志与调用证据

[官方非交互文档](https://learn.chatgpt.com/docs/non-interactive-mode)支持 `codex exec --json` 导出事件流，`--output-last-message` 保存最终答复；[App Server 文档](https://learn.chatgpt.com/docs/app-server)提供会话、技能发现和回合记录接口。

新样本使用新会话，固定历史场景按输入中的消息角色和顺序提交。开放场景使用同一会话接收事实卡回复。不要把多条历史消息拼成一条普通用户提示后仍称为原协议运行；不要用复用的作者聊天或继承评审上下文的 agent 作为基线。

- 逐轮保留原始事件、请求、实际用户回复、时间、退出状态和工具读取记录。最终答复之外的早期错误也进入对应事件指标。
- 技能被发现、正文被加载、模型遵守规则分别记录。显式正文注入可证明注入；实际文件读取可证明观察到读取。没有读取事件通常只能记为 `unknown`，不能仅凭回答风格声称加载或未加载。
- C2 沿用冻结的自然语言点名前缀。App Server 可以用 `skill` 输入项注入正文，但额外使用这种方式会改变 C2 调用机制；若研究该模式，需单独登记条件和协议。
- 保存宿主实际返回的 input / output / cache / reasoning 字段及其定义。缓存和推理字段可能是子集，不能重复相加；缺失字段记未知，不用字数估算 token。
- 保存全部技术失败及协议允许的一次重试。回答不佳是结果，不能用重跑覆盖。

## 本轮交付与完成标准

第一阶段为 48 个计划槽位：4 场景 × 1 个已登记配置 × 4 条件 × 3 次。真实采集后，按原量表进行盲评、记录分歧并裁决，再填入报告模板。应同时发布有利与不利案例、缺失数据和边界。

当前完成的是实验材料、隔离预检与 8 次单轮工程采集；其余 40 个槽位、独立人工校准与评分尚未完成，详见[首批报告](../../evals/runs/2026-10-11-codex-rc4-first-batch/REPORT.md)。README 可以展示已交付的安装和评估基础设施；效果百分比、建议采纳率及 token 节省比例需等到对应数据实际存在。合成场景不能估计真实用户采纳率。

真实演示另见[90 秒录制脚本](../demo-script.md)。单次使用演示用于说明产品流程，不替代对照评估。
