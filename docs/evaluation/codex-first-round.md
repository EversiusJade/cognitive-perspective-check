## 采集前登记

运行前，用[预登记模板](../../evals/experiment/preregistration-template.json)记录以下内容，另存为该批次的登记文件：

- 客户端与确切模型标识、推理设置、工具权限、系统指令和其他技能清单。本机当前设置为 `gpt-6-luna`、`medium`，尚未由模型服务确认版本。不可见参数及别名解析记为未知。
- C0 / Cs 的目录发现和正文读取隔离证据；C1 / C2 使用完全相同的技能文件。“无 skill”组不能靠关闭技能、禁止使用本项目等提示代替环境隔离。
- 两位独立人工评审的代号、校准记录、随机顺序及时间/调用预算。两次 AI 打分不能代替双人评分，作者不能是唯一裁决者。
- 输入、量表、协议和目标文件的哈希。发现预检不计入 48 个 pilot 槽位，也不从中挑选“更好”的输入或评分标准。

条件不全时，记录须明确标为“使用走查”，不能据此报告无 skill 的因果增益、自然调用率或正式 pilot 完成。

### 文件隔离需要核对的通道

正文还可从本机源码、ZIP 副本和公开 GitHub 获取。四条件须使用一致的有限工具环境，禁读评估材料及其他副本，并控制网络搜索、MCP 和连接器通道。本机另发现 65 个技能条目；未参与研究的规则须统一冻结或禁用，并记录最终环境。关闭和开启发现的两组都须重新核对。

[官方权限配置](https://learn.chatgpt.com/docs/permissions)支持命名权限配置和路径禁读，但沙箱权限主要约束本地命令，其他工具仍需单独控制。[Windows 沙箱说明](https://learn.chatgpt.com/docs/windows/windows-sandbox)列出了支持禁读的执行方式。须同时核对配置和实际执行。后续 MXC 预检观察到目标路径按条件开放、源码副本禁读，已发现的 MCP 和插件也被显式关闭；证据见首批报告。

## 日志与调用证据

[官方非交互文档](https://learn.chatgpt.com/docs/non-interactive-mode)支持 `codex exec --json` 导出事件流，`--output-last-message` 保存最终答复；[App Server 文档](https://learn.chatgpt.com/docs/app-server)提供会话、技能发现和回合记录接口。

每个新样本新建会话，固定历史场景按输入中的消息角色和顺序提交；开放场景在同一会话接收事实卡回复。将多条历史消息拼成一条用户提示，不符合原协议。基线不得复用作者聊天，也不得使用继承评审上下文的 agent。

- 逐轮保留原始事件、请求、实际用户回复、时间、退出状态和工具读取记录。早期错误也计入对应事件指标，不能只看最终答复。
- 分别记录技能发现、正文加载和规则执行。显式注入正文可证明注入，实际文件读取可证明观察到读取。没有读取事件通常只能记为 `unknown`，不能凭回答风格判断加载状态。
- C2 使用冻结的自然语言点名前缀。App Server 的 `skill` 输入项可注入正文，但额外注入会改变 C2 的调用机制；研究这种模式须另行登记条件和协议。
- 保存宿主返回的 input / output / cache / reasoning 字段及定义。缓存和推理字段可能是子集，不得重复相加；缺失记未知，不用字数估算 token。
- 保留全部技术失败和协议允许的一次重试。回答不佳也是结果，不得重跑覆盖。

## 本轮交付与完成标准

第一阶段计划 48 个槽位：4 场景 × 1 个已登记配置 × 4 条件 × 3 次。采集后按原量表盲评，记录并裁决分歧，再填写报告模板。有利和不利案例、缺失数据及结论边界一并发布。

目前已完成实验材料、隔离预检和 8 次单轮工程采集；其余 40 个槽位、独立人工校准与评分尚未完成，详见[首批报告](../../evals/runs/2026-10-11-codex-rc4-first-batch/REPORT.md)。README 可介绍已交付的安装和评估基础设施。效果百分比、建议采纳率和 token 节省比例须有对应实测数据；合成场景无法估计真实用户采纳率。

真实演示见[90 秒录制脚本](../demo-script.md)。单次演示说明产品流程，不能代替对照评估。
