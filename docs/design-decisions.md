# 设计决策与收束

当前候选版为 `0.2.0-rc.3`。本页记录可复核的论点与取舍；[研究目的](research-purpose.md) 定义完整工作流与待检验目标。主线是减少用户与 AI 预设造成的过早认知收窄，同时保持讨论与阅读有限。

| 审查问题 | 支持扩展的理由 | 限制或反证 | 本轮采用的规则 |
|---|---|---|---|
| 是否所有模糊问题都触发？ | 不完整背景可能遗漏关键关系 | 模糊表达也可能只需要一句改写；清楚背景仍可能遗漏关键视角 | 早期项目或决策中，只有视角差异会改变判断或行动时校准 |
| 是否理解需求后就完成？ | 准确理解是分析基础 | 澄清完成后，双方仍可能围绕同一预设展开 | 理解背景和规则后，继续识别核心问题、比较有效视角与取舍、给条件判断，由用户选深入 |
| 是否找出用户的“真正需求”？ | 需要区分目标与解法 | AI 也会强加自己的目标 | 提出暂定理解；明确目标不被擅自替换 |
| 是否逐项确认背景？ | 理解目标、规则及因果关系可能提升判断 | 无关信息增加追问和退出成本 | 先提炼已有信息的内在逻辑，再检验两种答案各会改变什么；通常零或一个问题 |
| 是否每轮重新确认方向？ | 可以保持用户参与 | 已确认的范围被反复打断 | 初始累计最多三问；只有新信息实质改变范围才重开对齐 |
| 是否必须形成对立面？ | 能发现原预设遗漏 | 假反对、假平衡可能误导 | 通常两个、最多三个有实际后果的视角，保留原方案的最强合理利益 |
| 是否只给问题让用户自己想？ | 用户参与能帮助理解 | 用户仍没有可用的第一步 | A 阶段必须给一份有用的有限判断和条件建议 |
| 是否把推演当论据？ | 可显示因果后果和潜在失败 | 情节合理不能证明真实世界会发生 | 推演标为假设，用来发现要查的事实，不制造证据 |
| 是否默认比较所有利益相关方？ | 可发现被遗漏的成本 | 固定维度增加阅读负担 | 只引入会改变本次选择的维度 |
| 是否给出普遍最优解？ | 明确偏向便于行动 | 证据不完备，目标与价值取舍也不同 | 比较基于现有证据；AI 偏向基于明确优先级与假设，并说明改变条件 |
| 是否一定选出一条最佳路线？ | 用户希望得到建议 | 未知优先级可能被 AI 自己补齐 | 无依据时不硬排序，说明各路线成立条件并给可区分路径的下一步 |
| 是否用户选执行后只给交接卡？ | 摘要能保持目标与约束 | 用户已授权的成果可能被延后 | 直接完成所选方案、文案或文件；仅在确需转交时给交接 |
| 是否做多角色辩论？ | 表面上提供多立场 | 未保证独立性，增加调用和呈现成本 | 单次校准同时检验用户与 AI；用户另有要求时才扩大 |
| 是否做“全平台一键安装”？ | 更容易传播 | 客户端发现机制各不相同 | 优先 Windows Copilot；共用目录、手动安装作明确补充 |
| 是否宣称严格省 token？ | 易理解的卖点 | 纯 skill 无法控制后台推理计费 | 只承诺行为约束；实测数据不足时不承诺节省比例 |

## 采用的方向与保留选项

**当前主线：有限且连续的早期问题分析。** 从抽象或不完整的背景进入，理解目标、规则和关键关系；背景已经清楚时可以直接分析。围绕核心问题比较少量实质不同的视角、证据与取舍，给出条件判断，再由用户选择验证、路线比较、推演或执行交接。每段都服务于减少认知收窄，不能只完成需求澄清便宣称达到目的。难点是误触发、AI 自己的框架强加，以及强模型本身已有相近能力，附加价值需要验证。

**保留选项：显式的假设验证卡。** “关键假设、支持或削弱它的观察、最小验证、结果怎样影响选择”可作为用户选中验证分支后的短交付物。已知问题的用户也可直接请求它。固定交付物便于检查，但不能覆盖前面的背景理解与视角比较；是否拆成独立 skill，等待真实案例支持。

当前保持一个入口和按选择深入的参考文件，不通过增加技能数量证明差异化。

## 运行分支

| 条件 | 本轮交付 | 停止条件 |
|---|---|---|
| 明确、已选定的任务 | 直接完成；有实质问题才加短提醒 | 请求的交付物完成 |
| 早期项目或决策，视角可能改变行动 | 工作理解、必要补问、核心问题、有效视角的依据与取舍、条件建议 | 用户已有足够信息选择，或需要事实验证 |
| 关键事实未知 | 最小验证方法或用户提供证据后的更新 | 无可获得的新证据时停止推测 |
| 用户选路线比较 | 沿用已确认目标，只比较本次选择有关的少数标准，说明各路线成立条件 | 剩下是价值取舍或关键事实待查 |
| 用户选沙盘推演 | 最多三个关键节点、一个可能失败方向、观察信号 | 所选情景已解释清楚 |
| 用户选择制作或执行 | 所选范围的可用方案、文案或文件，按需携带约束与修正条件；确需转交时才给交接 | 请求的成果完成，或清楚说明真实缺口与待办 |

## 成熟度与下一轮收束

当前定位为可安装候选版，不能把作者或独立代理的静态审查等同于已证明有用。已有验证记录对应 `0.2.0-rc.1`，保留为历史记录；本轮没有新增模型行为试验，内容审查见 [本轮记录](reviews/v0.2.0-rc.3-content-review.md)。成为稳定版需要实际客户端中发现、明确调用、自然调用、连续对话与任务执行的记录；还需要真实使用者判断理解是否准确、视角是否影响选择、比较是否有依据、所选成果能否直接使用、是否增加不必要阅读。

下一轮优先依据失败修改：误触发和阻塞明确任务优先；错误推定用户目标其次；缺乏实际后果的替代框架再次。只有出现这些问题才增补核心规则。新的功能点先进入真实案例，不直接扩写入口。
