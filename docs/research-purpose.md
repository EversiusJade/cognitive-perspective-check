# 研究目的

本项目关注早期项目、设计和决策讨论中的认知窄化：在关键假设还没有检查时，就把一种解释或路线当作唯一选择。用户可能先认定原因，也可能先选定工具；AI 则可能过早相信自己的理解，继续围绕它生成方案。

背景不完整会增加这种风险，因此需要少量澄清。但背景已经清楚，也可能存在值得检查的前提。项目关注从理解到判断的整个过程，希望用户既能看见遗漏，也能得到下一步可用的建议或成果。

## 讨论应怎样推进

先利用用户已经提供的信息，识别目标、约束、观察和拟议解法。只有一个未知会影响建议时，才值得补问。问题要简短，通常零问或一问；初始澄清累计最多三项关键信息，不能用一串复合问题绕过限额。无法补齐的信息保留为未知。

接着检查用户与 AI 各自依赖的假设。通常比较当前视角和一个替代视角，默认最多三个。每个视角都应影响行动、评价标准或取舍，否则没有必要占用回答篇幅。比较需要保留原路线的合理利益，也不能为了形式对称而制造反对意见。

建议的理由要能追溯到用户观察、可靠来源或明确标出的假设。AI 可以表达偏向，但应说明在什么条件下成立，以及什么信息会让建议改变。证据不足以排序时，先说明各路线的适用条件，并提出能够区分它们的检查。

首轮应交付可用判断；用户已经要求方案、文案或文件时，尽可能当轮完成。后续按用户选择验证、比较或推演，默认只深入一个分支。新信息出现后，修正受影响的部分即可，不必重开全部讨论。推演解释假设的后果，不构成现实证据。

用户的明确目标、约束和价值取舍需要保留。AI 建议改变它们时，应把改动说清楚，不能自行替换。最终选择与讨论深度由用户决定。

## 准备观察什么

| 要检验的问题 | 可观察的表现 |
|---|---|
| 少量补问能否帮助理解？ | 目标和约束被保留；推断有标记；补问的不同答案会改变建议；已知信息没有被反复询问。 |
| 替代视角是否影响选择？ | 第一行动或评价标准有实际差别；原路线的价值被说明；没有只更换实现方式或硬找反面。 |
| 建议是否有依据？ | 事实、推断与价值偏好可区分；理由与本次目标有关；成立条件和改变条件清楚；模拟没有被当成事实。 |
| 讨论能否推进到成果？ | 后续工作沿用已确认背景，遵守所选范围；交付物可用；没有多余的追问、展开或反复确认。 |

回答符合这些要求，只能说明规则得到了遵守。要判断是否有额外价值，还需要相同条件下的基线比较，以及真实用户对理解、选择和后续行动的反馈。回合数、可见篇幅、时延和宿主提供的 token 用量可以记录；无法获得的指标记为未知。

## 现有证据

`rc.1` 的安装检查和小样本行为记录保留在 [历史验证](../evals/validation.md)，`rc.4` 发布时的内容审查见 [使用走查](reviews/v0.2.0-rc.4-use-review.md)。这些记录各有范围，不能直接推广为当前版本的效果结论。

之后完成的 [8 次 Codex 采集](../evals/runs/2026-10-11-codex-rc4-first-batch/REPORT.md) 包含两个单轮场景、四种条件和原生用量。它记录了额外说明与工具读取失败等现象，尚未覆盖探索性决策的增益，也没有独立人工评分。完整首轮计划还剩 40 次采集。

项目目前不承诺消除偏差、穷尽视角或找到普遍最优解。专业判断仍需要相应领域方法和可靠事实；有限对话也无法直接限制模型后台推理成本。真实使用案例可通过 [反馈模板](https://github.com/EversiusJade/cognitive-perspective-check/issues/new?template=usage-feedback.md) 提供。
