# rc.7 Review

日期：2026-10-17。

## 检查范围

对照 rc.6 的核心规则、深入分支、README、安装说明和发布流程，做了一次规则与文档静态 review。结论来自文本检查，没有做独立人工盲评或模型行为实验。

## 发现与修改

- 原有完成检查侧重成果和格式，没有明确要求检查最终建议的证据与假设。增加交付前 review，检查目标、视角、支持依据和条件建议。
- review 如果变成第二轮分析，可能让已确定任务重新出现比较和提问。因此，固定执行任务只检查成果，不重新讨论决策，也不增加提问或视角限额。
- 新 review 可能与 A 阶段、深入交付分支的完成检查重复。明确共用同一次 review，替换重复检查。
- 默认公开检查清单可能增加阅读负担，自查也容易被误写成独立验证。只说明影响用户选择的修正和缺口，按需展开；独立验证必须有实际执行记录。
- 当前本机安装入口仍标为 rc.4，落后于仓库 rc.6。发布 rc.7 后，将本机入口和支持文件同步为 rc.7。

## 何时结束

修正实质问题后交付。缺少证据时，说明结论的条件和下一项有效检查，不反复自辩，也不为 review 自动启动工具。

这次没有执行新的客户端或模型行为测试。是否遵守一次 review、是否减少判断错误，以及 token 成本如何，需要后续对照观察。
