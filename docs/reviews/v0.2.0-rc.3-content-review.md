# v0.2.0-rc.3 内容审查

日期：2026-10-11。本轮是静态内容审查，不是模型行为实验。发现的是文字规则可能引起的风险；以下修订不代表已观察到模型失败，也不证明效果提高。

## 多维检查与修订

| 维度 | 本轮结论与处理 |
|---|---|
| 适用范围 | 保持早期项目、设计与未定决策；普通事实、明确执行直接完成。 |
| 背景理解 | 提炼关键关系，少问会改变方向的信息；按信息项计算问题数，不能用复合问句绕过上限。未知仍标为未知。 |
| 目标自主权 | 同一目标与约束下比较；新目标或优先级是待选提议。历史上下文不能证明用户当前偏好。 |
| 视角差异 | 视角应改变行动、标准或取舍；保留原路线利益。框架已充分成立时，可以比较具体实现。 |
| 论据 | 关键支持追溯到用户观察或来源；没有依据则标假设，推演不能充当现实证据。 |
| 建议排序 | 有依据才给条件偏向；无法合理排序时，说明各路线成立条件与下一步。最小验证必须能区分路线。 |
| 选定成果 | A 在可能时直接交付用户所需的可用产物；B 制作所选成果，不以规格卡或流程模板代替完成。 |
| 成本 | 保持少量问题、视角和单个深入分支；不增加固定表格，不承诺后台 token 硬上限。 |
| 安装分发 | 沿用安装入口与纯 skill 包；内容审查不等于实际客户端安装、发现或自然调用已验证。 |

## 三条设计路径的取舍

- 纯澄清：入口短、容易结束，但理解需求后仍可能围绕同一预设展开，不能覆盖本项目目的。
- 广泛多角色讨论：可扩展立场，但角色不保证独立证据，容易增加阅读和调用成本。
- 当前有限连续流程：理解背景、检查双方预设、比较少量视角、给条件判断，再交付用户选中的成果。覆盖主旨，也承担误触发和 AI 强加框架的风险。

本轮没有采用固定分析维度、角色委员会、无依据打分或新增 skill。组合设计和成果边界更清楚；相近项目也有少问、批判性思考和 AI 输出检查，尚无竞品胜出证据。

## 剩余验证与发布状态

后续需要真实用户评价：理解是否准确、视角是否改变选择、产物是否可用、阅读负担是否合理；实际客户端还需观察明确调用、自然调用及连续纠正。没有新增这些试验，历史记录不能替代本版验证。
