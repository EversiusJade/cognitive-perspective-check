# rc.4 Skill 使用审查

日期：2026-10-11。用户授权直接补齐实际使用缺口。这次根据已知目标、现有文件和独立静态审阅修订，没有做新的模型行为试验。

## 为什么这样改

目标是减少用户与 AI 过早认知收窄，提供可用的判断，并完成用户选中的成果。rc.3 已覆盖关键背景、双方预设、有效视角、证据取舍、条件建议和交付。少量背景问题已足够明确这次的方向，无需再问。

继续扩充分析规则和分支，可以为复杂情境提供更明确的提示。但没有新的使用失败支持这种扩展，继续增加规则也容易抬高入口成本，因此这次没有采用。

这次选择保留范围，补充交付要求和覆盖限制，精简入口，减少重复指令，明确何时需要纠正，也方便收集真实使用反馈。是否有效，仍需实际观察。

依据来自文本审查：主流程完整，但首轮视角可能被误读为已经穷尽，成果完成还缺一项简明的交付检查，入口也有可合并的重复内容。若真实案例显示关键关系没有覆盖，再考虑有针对性地扩展。

## 具体修改

- 明确视角数量只限制当次展开，不表示已经穷尽；只提示会影响建议的未评估因素。
- 新背景使旧视角失效时，替换受影响部分，避免历史分支持续累积。
- 交付前按请求的目标、约束和格式检查一次。区分提出的方案与已执行动作，不反复增加自评。
- 用户明确选择更广范围和预算时，按其要求展开，不受默认单分支与覆盖限额约束，也不重复索要确认。
- 合并入口的重复文字，保留目标保护、少问、行动差异、证据边界、条件判断和停止条件。文字变短不等于后台 token 已减少。
- 增加简短的使用反馈模板，最少提供原问题、实际回答，以及带来的帮助或阻碍；未填数据不补造。
- 同步发布资料：GitHub About 已采用减少双方认知窄化的简介，八个 Topics 已通过 API 确认生效。

## 还需要什么证据

新版自然调用、真实用户收益、相对强模型或竞品的增益，以及 token 与时延，都需要实际记录。这次没有新增测试或行为实验，假设使用、作者演示和静态审阅均不作为效果证据。

最终的独立静态复核未发现精简丢失既有核心要求的实质问题。这只能说明内容一致，不能证明模型行为效果。

达到这次的完成条件后停止扩写：规则可读，成果标准具体，分发文件一致，并有真实案例的反馈入口。
