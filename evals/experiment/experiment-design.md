# Cognitive Perspective Check 对照实验方案 · 修订版

方案版本：1.0；日期：2026-10-11；目标 skill：0.2.0-rc.4。

状态：实验文档和评分规则已准备；尚未运行本方案的模型实验。
这份文档可放在 evals/experiment/。inputs.json、rubric.json 与记录模板构成可交接的运行资料；实际客户端、模型版本、技能可见状态和评审人员须在开跑前登记。原始 Kimi 方案保存在 source-kimi.md。

## 1. 目的、证据与研究范围

本实验研究：在早期项目、设计和未定决策中，skill 能否在有限成本内帮助 AI 理解关键背景、检查双方预设、比较有依据且影响行动的视角，并交付用户需要的判断或成果。

测量对象是可观察的回答、对话轨迹与运行成本。多列角度、增加提问或改变行动本身不等于减少认知窄化；必须保留用户明确目标、尊重证据并服务当前任务。文本评分不能证明用户长期认知能力提高。

现有 validation.md 仅记录 rc.1 的有限检查，不能证明 rc.4 合规或有效。rc.4 的静态走查也不是行为实验。“付费试讲推演偏乐观”暂列待验证风险：未提供对应版本的原始回答前，不称为已证实回归。

| 问题 | 测量与主要比较 | 结论边界 |
|---|---|---|
| RQ1 有何实际收益？ | C2−C0、C1−C0 的合格交付与有效视角差值 | 仅适用于本场景集与运行配置 |
| RQ2 完整 skill 的额外价值在哪里？ | C2−Cs：完整 skill 与固定简短提示的比较 | 不能据此宣称优于其他完整 skills |
| RQ3 是否正确使用与停止？ | 累计补问、按阶段的范围合规、已选分支交付、负样本冗余分析 | 合规与用户效用分别报告 |
| RQ4 不点名时实际发生什么？ | C1 的技能加载证据和目标行为，分别统计 | 无完整调用记录时，实际加载率未知 |
| RQ5 增益增加多少成本？ | 完整会话可观察 token、时延、用户回复数和输出长度 | 成本比例不能单独证明“值得” |

## 2. 四条件、配置和规模

采用同一场景在各条件下的配对比较；这是场景内设计，目前没有真人被试实验。

| 条件 | 目标 skill 状态 | 当前用户消息的固定前缀 |
|---|---|---|
| C0 默认 | 对模型不可见，不能读取正文 | 无 |
| Cs 简短提示 | 与 C0 相同 | 下方固定简短提示 |
| C1 自然可用 | 元数据可见，客户端允许选择；用户未点名 | 无 |
| C2 显式 | 与 C1 相同 | 使用 cognitive-perspective-check。\n |

Cs 的固定文本：

> 先理解关键背景，只补问会改变判断的信息；保留用户明确的目标和约束，检查用户与 AI 的预设，比较少量有依据且会改变行动或取舍的视角，说明条件建议；已明确的任务或已选分支直接交付，不重复展开。

前缀只加在固定对话中最后一条用户消息前；不改写历史消息。逐轮用户回答不重复添加。所有条件接收同一场景事实与同一答复政策。

- Pilot：4 场景 × 1 个客户端与模型配置 × 4 条件 × 3 次重复＝48 个计划槽位。
- 诊断扩展：8 场景 × 2 个配置 × 4 条件 × 3 次重复＝192 个计划槽位。
- 48 和 192 是场景运行槽位，不是独立用户或独立问题数量。重复用于观察同一问题的不稳定性。
- Pilot 若改变输入、评分、运行或答复政策，扩展阶段重新冻结并生成完整 192 个槽位；不得把旧 pilot 混入新协议。若完全未变，可复用重合的 48 个槽位，追加 144 次，明确列出复用记录。
- 两个配置各自比较四条件。若一个来自 Copilot、另一个来自 Codex，则称为“两个模型与客户端组合”，不把差异归因于模型或客户端中的某一个。
- 如后续修改 skill，另建版本组，不与 rc.4 合并。独立确认阶段需新场景、独立评审和另行冻结的协议，本方案不把诊断扩展改称确认实验。

## 3. 冻结场景与用户答复

inputs.json 已固定以下八个诊断场景，其中四个用于 pilot。原 prompt 或历史消息逐字保留，评审要求与背景事实卡只供执行者和评审使用，不发送给被测模型。

| 场景 | 阶段 | Pilot | 主要检查 |
|---|---|---|---|
| messy-context-reconstruction | 开放初始讨论 | 是 | 背景理解、关键补问、不同解释与短方案 |
| solution-first-vague-context | 开放初始讨论 | 否 | 收益目标与 App 手段、保留请求的功能清单 |
| fixed-deliverable-causal-preset | 明确交付 | 是 | 不确认方向、自然邀约不超过 80 字 |
| preserve-explicit-learning-goal | 未定方案 | 否 | 保留学木工目标，600 元与两天约束 |
| chosen-pilot-simulation | 已选分支的下一轮 | 是 | 付费试讲、500 元、实际信号、失败路径 |
| multi-turn-initial-cap | 已有三项补问的下一轮 | 否 | 不重启问卷、按已知资料交付知识库方案 |
| simple-task-no-calibration | 负样本：简单事实 | 否 | 直接换算，无访谈或多视角流程 |
| plain-chat-no-calibration | 负样本：明确简短改写 | 是 | 只交付一句话 |

固定历史场景只检查给定背景下的下一轮响应；不声称验证整段对话是否由模型自主生成。

### 开放场景的统一答复政策

1. 每个 run 使用独立会话。开放场景最多三次模型回复；已选分支、明确执行和固定历史续轮只生成一次回复。
2. 模型提出背景问题时，执行者按 facts_card 仅回答实际问到的项目；不得提前透露整张事实卡。卡片未给出的内容统一答“暂不清楚，请保留为未知，按现有信息作条件分析。”
3. 重复问题只重复既有答案，不额外补充。一个复合问句按独立信息项计数。一次问四项就是四项，不能因有一个问号变成一项。
4. 达到轮数上限时先结束，不再发送答复。若背景问题和成果同轮出现，可回答背景问题后获取更新；已交付后的可选继续菜单不算待答背景问题。
5. 若只有继续菜单或空泛框架、没有可用成果，最多回复一次固定请求：“请基于已有信息给出当前范围内可用的简短方案；未知处保持条件性，不展开其他分支。”
6. 用户要求选择深入路线时，默认不授权新分支；只要求完成当前交付。既有“已选试讲”场景承接已给出的授权。
7. 没有背景问题、已经出现请求的成果形式时结束，不根据质量评分追问改进。没有问题、没有成果、也不是待补救菜单/框架的回答（包括拒绝或直接改错目标）立即结束，记为有效观察。第二次仍只给菜单时结束，不能无限补救到成功。
8. 问题超出 skill 的三项上限时，仍按同一事实卡回答并记录违规，不悄悄截断为合规。

每次实际用户回复保存原文及所用事实卡字段。答复保持原任务语言；英文场景使用inputs中固定英文事实与回复。这些是构造的诊断环境事实，不是现实团队或商店的数据。停止只按问题/成果形式和轮数判定，合格性由后续评审决定，不向被测模型泄露量表。

## 4. 运行隔离、证据与失败政策

### 开跑前

- 用 preregistration-template.json 登记配置、确切模型标识与版本、客户端版本、可控采样设置、系统指令及其他技能、工具权限、评审人员、顺序随机种子和时间／费用预算；不可见字段记 unknown 并说明。
- 保存目标四个文件的 SHA256、版本标签和可解析的仓库 revision（可获得时）；manifest.json 绑定当前本地文件，不把尚未查询的远程 commit 写成已知。
- 在各条件保存实际技能清单或同等证据：C0/Cs 的模型上下文不含目标名称、描述或正文；C1/C2 的可见性与权限一致。
- 新会话不能清除全局预加载。不能隔离时，该配置不适合回答无 skill 的因果比较；应改为可隔离运行环境，或明确转为非对照观察。
- 独立执行者只接收条件所需内容、场景输入和实际用户回复。不得接收评分锚点、预期答案、作者评价或其他条件输出。

### 每个计划槽位

按“配置 × 场景 × 重复”的区组随机排列四条件并交错运行。保存顺序与随机种子；不先跑完全部 C0 再跑 C2。每个 run 保存完整原始消息、最终回答、事件轨迹（若支持）、元数据和可观察用量。

不要仅在某个条件注入“列出已用技能”的询问，那会改变任务和路由。采集应依靠宿主记录或一致的外部观察。

### 技术失败与有效观察

仅预先定义的提交未成功、服务错误、网络中断或客户端崩溃可技术重试一次。保留原尝试、错误、可观察成本，并关联替代 run；再次技术失败记 missing。

拒绝回答、跑偏、过长、未交付、重复确认和不必要工具调用属于有效行为观察，不能重跑挑选更好答案。异常格式能读时按原文评分；事件记录缺失但回答有效时，保留质量评分，将调用／成本字段记 unknown。

报告同时列出有效输出成本和取得这些输出的全部尝试成本。预算触顶或实际模型版本变化时暂停采集，报告已完成槽位和原因，不用低成本条件替换未完成条件。

## 5. 量表、适用性和人工评分

rubric.json 定义锚点，inputs.json 为每个场景冻结适用项与最低成果。正向指标 1＝满足，0＝适用但不满足，NA＝输入已预定不适用。漏做要求不能改成 NA。

核心质量项：关键背景理解、有效视角、条件建议、目标与约束、证据完整性、可用交付、已选分支范围、推演可核查性。

诊断项：补问价值、冗余展开、虚构事实、初始累计信息项、视角数量、首轮和全会话字符数。后两项风险指标以 1 表示风险出现。

质量与证据评分只依据该run中模型实际收到的消息、控制者回复和可审计工具结果。未发送的facts_card字段不是模型已知事实；遗漏不扣分，猜中也不构成证据。评审必须核对实际发送轨迹。

补问价值是动态诊断项：未生成背景请求记NA；生成至少一项时检查所有新增请求，固定历史里的问题不参与该项评分。它不进入合格交付率的必需项。

成果满足性按结束时明确提交的最终成果评分；无修订说明时取最后提交的成果，不从多版中挑最好的一版。关键背景、有效视角、条件建议和推演结构按最终判断/成果评价；目标与硬约束、证据完整性、已选分支范围及风险项检查完整生成轨迹。前轮虚构事实、明确改错目标或未授权扩张不能因末轮省略而消失。明确标注的可修正假设随新背景更新，不自动算错误改目标。

- 四条件使用相同任务质量要求。没有 A/B 标签、固定标题、事实／推断字样或选择菜单，均不自动扣分。
- 同一目标内至少两个有依据且影响行动、评价或取舍的理解才能算有效视角；步骤、标题、措辞变化、一次推演的成功与失败结果不自动算多个视角。
- 默认“两个视角”是常见形式，最多三个是适用讨论中的 skill 边界；不把所有任务都要求为 2–3 个。质量比较与 C1/C2 的协议合规分别报告。
- 提问按初始对齐累计索取的信息项，包括给定前文。已回答三项后再次索取第四项就是违规。通常零问或一问不作为所有场景的硬上限。
- 支撑可以来自输入事实或明确标注的假设。未查得的事实不能写成已观察；无需检索的构造场景不要求额外联网。
- 提议的试讲价格、预算分配和检验阈值是设计参数，必须明确为提议并符合约束。指定的试讲场景禁止虚构报名率，不能借“假设”标签绕过该约束。
- 有限推演必须连接实际可检查信号与后续动作，并覆盖至少一个重要的不利或未知结果；不得将问询人数推成付款或市场规模的证据。
- 明确交付当轮可做时直接交付；开放讨论允许关键补问后在固定轮数内完成。不得通过短首轮延期交付获得成本优势。

### 双人评审

两位评审独立评分；尽量至少一位不是作者。先用 calibration-examples.md 的四个作者构造例子校准，例子不属于正式 run、也不是模型效果数据。

评审包包含原始任务与用户回复、输出和阶段要求，隐藏条件、模型配置、用量及运行顺序。如统一遮盖输出中的 skill 名称，保留原始档案和遮盖规则；不重写内容或风格。作者可能辨认自身提示或样例，须披露盲法局限。

每项附原文位置与判定理由；缺失记“未找到”并引用输入要求。先保留两位原始评分，再讨论或第三方裁决。报告裁决前一致率、分歧数量和最终评分；一致率高不等于指标有效。AI 可辅助整理和定位，不能替代全部人工评分；同为提示工程并不构成形式上的循环论证，主要风险是共同偏差与缺少独立验证。

## 6. 主要结果、统计口径与诊断旗标

### 主要结果

合格交付率：一个 run 的全部场景必需质量项为 1，且适用的冗余展开／虚构事实风险为 0。每个场景的必需项在 inputs.json 冻结；评分要求不得根据某个条件的输出临时增加。

有效视角率：只在预设为需要视角比较的场景统计；必须有明确目标内的合理差异和选择依据。独立报告，避免只靠总体交付率掩盖视角问题。

优先比较 C2−Cs，检查完整 skill 的额外价值；C2−C0 与 C1−C0 作为预定次要比较。C1 保留所有有效输出，不只挑已加载的回答比较，以反映实际可用状态的效果。按加载状态分组只作描述性补充。

先计算每场景各条件三次有效运行的平均得分，再对场景等权聚合；两个配置分别报告。NA 不进入对应指标分母；应当评分却因技术故障不可评分的为 missing，不能换成 NA。配对比较只用两条件都有有效数据的场景，列出实际次数和缺失；任何未满三次的区组不得据以宣称通过诊断旗标。

只报告配对差值、每场景结果和重复波动。本方案不把 48／192 次当成独立场景样本，不默认计算具有确认性含义的显著性结论。

### Pilot 后用于定位问题的旗标

这些阈值是项目维护用的启发式诊断，不是经验证的科学界限或“成熟／有效”的证明：

| 旗标 | 完整诊断扩展中的口径 | 出现时处理 |
|---|---|---|
| D1 额外价值不足 | C2−Cs 的有效视角率差值 ≤0 | 检查简单提示是否已足够；暂不宣称完整 skill 有额外优势 |
| D2 交付受损 | C2−Cs 或 C1−C0 的合格交付差值 <0 | 优先定位阻塞交付、错误改目标和展开过度 |
| D3 协议不稳 | 每个配置的C1、C2分别计算适用上限联合合规率；初始信息项≤3且单轮最大视角数≤3，场景等权结果<80% | 查失败原因；不自动追加更严数字规则 |
| D4 成本压力 | 某配置中完整可比会话的逐场景 C2/Cs token 平均比值 >1.5 | 与收益并列报告，定位额外读取、重复和延期成本 |

删除原“≥30pp 或相对两倍”的可替代门槛，也不把 C2 称为效果上限。C2 可能不如 C1 或 Cs。D3 的 80% 与 D4 的 1.5 倍仅保留为历史方案中的诊断参数，后续如改，须冻结新协议，不能追溯用新阈值宣布旧数据达标。

视角数量取每次生成回复中对照数量的最大值；跨轮重复或替换失效视角不累计历史总数。D3每个run中任一适用上限超限即不合规，两项均不适用则NA；C1与C2不混合分母。提问合规含固定历史已索取的信息项。

## 7. 加载证据、负样本与成本

### 加载与行为分开记录

- installed 与 catalog_visible 只说明文件就位／元数据可见。
- body_load_status：observed_loaded（可靠轨迹显示目标正文被提供或读取）、observed_not_loaded（宿主完整记录足以确认未加载）、unknown（轨迹不足）。
- 模型自述“使用 skill”单独记录，不能证明实际加载。正文加载也不保证执行正确。
- C1 正样本的可证加载率只在具备完整可审计记录的 run 中统计，同时报告已观测加载数、未知数及各自分母。
- C1 负样本的目标正文加载记录和冗余流程率分别报告。加载后直接执行与加载后过度分析是不同结果。实际用户体验问题由后者描述。
- C0 的目标行为出现率也要统计；出现条件建议或保留选择权不得被反推为 skill 已调用。
- 无完整记录时删除“自然触发 ≥50%、误触发 ≤20%”通过结论，保留目标行为与不必要流程的观察结果。

### 成本口径

记录每次尝试、每轮可获得的 input_tokens、output_tokens、cached_input_tokens、reasoning_tokens 和时延，同时记录提供者对字段的定义。reasoning／cache 若为输入或输出的子集，不能重复相加。

仅当输入和输出计数定义一致且覆盖同等完整会话时，可用 input+output 作可观察总量。包括技能读取、工具结果和必要用户回复（宿主有计数时）；无法确认覆盖则标 partial，不进行总 token 倍数判断。隐藏推理缺失记 unknown，不用字数换算填补。

首轮字符数和全会话助手字符数采用 Unicode code point 数，包含 Markdown、标点、空格与换行。它不是英文 word 数，不证明“一屏”或阅读时间。邀约等限长成果另按纯成果文本计数，包含标点与空格。

同时报告到首次可用结果的时间、会话总时延、用户回复次数和要求回答的信息项数。保存每轮提交/返回时间、用户或控制者等待时间；模型服务时延排除人工答复等待，与端到端耗时分别报告。首次可用结果由评审定位，始终未交付记NA，不能以短失败代替快速完成。方案预算由 preregistration 登记；无已选配置的实际单价，不预估费用或承诺节省。D4 在可比 token 数据缺失时记“无法判定”。C1、C0 的成本也展示，不只比较 C2。

## 8. 冻结、报告、维护和停止

### 开跑顺序

1. 登记模型与客户端、预算、其他指令和技能，确认四条件能隔离。
2. 确定两位评审，校准四个独立作者示例。
3. 完成 preregistration，冻结 inputs、rubric、短提示、事实卡、模型设置和 SHA；导出随机顺序与匿名映射。
4. 采集 48 个 pilot 槽位，保留全部尝试、实际回复和轨迹。评分前不改量表。
5. 仅检查流程可执行性、分歧和失败类型。若修改，保留旧协议并冻结新版本。
6. 在预算内进行 192 槽位诊断扩展；不能隔离或预算不够时如实报告已完成部分。
7. 依 REPORT-template.md 输出完整场景表、差值、成本、未知／缺失、裁决前一致性和失败例。成功与失败原文均引用。
8. 结果绑定版本和配置；失败修正后新版本另跑对应回归，不把原始失败覆盖成成功。

README 只能根据实际结果写“在某版本、某配置、某构造场景集中观察到某项差值”；保留缺失、例外和成本。不能写已证明普遍减少认知窄化、节省固定 token 比例、具有长期用户效果，或优于未比较的 skills。实验未运行时保留现有验证边界。

### 本轮停止条件

文档、输入、量表、模板与版本关联足以交给执行者；已完成静态一致性修订，即停止增加规则。真实加载率、评分结果、模型收益和成本需要实际采集。本轮不填造结果。
