# Cognitive Perspective Check 对照实验方案 · 修订版

方案版本：1.0；日期：2026-10-11；目标 skill：0.2.0-rc.4。

状态：实验文档和评分规则已备齐，尚未运行本方案的模型实验。

本文可存放在 evals/experiment/，与 inputs.json、rubric.json、记录模板一起交给执行者。运行前须登记实际客户端、模型版本、技能可见状态和评审人员。原始 Kimi 方案保存在 source-kimi.md。

## 1. 目的、证据与研究范围

实验检查：在早期项目、设计和未定决策中，skill 能否以有限成本帮助 AI 理解关键背景、检查双方预设、比较有依据且影响行动的视角，并交付用户需要的判断或成果。

测量范围为可观察的回答、对话轨迹和运行成本。增加角度、提问或改变行动，不能单独说明认知窄化有所减少；回答还须保留用户明确目标、尊重证据并服务当前任务。文本评分无法证明用户长期认知能力提高。

validation.md 只记录 rc.1 的有限检查，不能证明 rc.4 合规或有效；rc.4 的静态走查也不能代替行为实验。“付费试讲推演偏乐观”仍是待验证风险，取得对应版本的原始回答前，不认定为已证实回归。

| 问题 | 测量与主要比较 | 结论边界 |
|---|---|---|
| RQ1 有何实际收益？ | C2−C0、C1−C0 的合格交付与有效视角差值 | 仅适用于本场景集与运行配置 |
| RQ2 完整 skill 的额外价值在哪里？ | C2−Cs：完整 skill 与固定简短提示的比较 | 不能据此宣称优于其他完整 skills |
| RQ3 是否正确使用与停止？ | 累计补问、按阶段的范围合规、已选分支交付、负样本冗余分析 | 合规与用户效用分别报告 |
| RQ4 不点名时实际发生什么？ | C1 的技能加载证据和目标行为，分别统计 | 无完整调用记录时，实际加载率未知 |
| RQ5 增益增加多少成本？ | 完整会话可观察 token、时延、用户回复数和输出长度 | 成本比例不能单独证明“值得” |

## 2. 四条件、配置和规模

同一场景在各条件下配对比较，属于场景内设计，目前没有真人被试实验。

| 条件 | 目标 skill 状态 | 当前用户消息的固定前缀 |
|---|---|---|
| C0 默认 | 对模型不可见，不能读取正文 | 无 |
| Cs 简短提示 | 与 C0 相同 | 下方固定简短提示 |
| C1 自然可用 | 元数据可见，客户端允许选择；用户未点名 | 无 |
| C2 显式 | 与 C1 相同 | 使用 cognitive-perspective-check。\n |

Cs 的固定文本：

> 先理解关键背景，只补问会改变判断的信息；保留用户明确的目标和约束，检查用户与 AI 的预设，比较少量有依据且会改变行动或取舍的视角，说明条件建议；已明确的任务或已选分支直接交付，不重复展开。

前缀只加在固定对话的最后一条用户消息前，历史消息保持原文，后续用户回复不再添加。四条件使用相同的场景事实和答复政策。

- Pilot：4 场景 × 1 个客户端与模型配置 × 4 条件 × 3 次重复＝48 个计划槽位。
- 诊断扩展：8 场景 × 2 个配置 × 4 条件 × 3 次重复＝192 个计划槽位。
- 48 和 192 计的是场景运行槽位，不能当作独立用户或独立问题数。重复运行用于观察同一问题的不稳定性。
- Pilot 若改过输入、评分、运行或答复政策，扩展阶段须重新冻结协议并生成完整 192 个槽位，不得混入旧 pilot。完全未变时可复用重合的 48 个槽位，追加 144 次，并列明复用记录。
- 两个配置分别比较四条件。若一个来自 Copilot、另一个来自 Codex，应称“两个模型与客户端组合”，不能单独归因于模型或客户端。
- 后续修改 skill 须另建版本组，不与 rc.4 合并。独立确认阶段需要新场景、独立评审和另行冻结的协议；本方案的诊断扩展不能改称确认实验。

## 3. 冻结场景与用户答复

inputs.json 已冻结八个诊断场景，其中四个用于 pilot。原 prompt 和历史消息逐字保留；评审要求与背景事实卡只供执行者和评审使用，不发送给被测模型。

| 场景 | 阶段 | Pilot | 主要检查 |
|---|---|---|---|
| messy-context-reconstruction | 开放初始讨论 | 是 | 背景理解、关键补问、不同解释与短方案 |
| solution-first-vague-context | 开放初始讨论 | 否 | 收益目标与 App 手段、保留请求的功能清单 |
| fixed-deliverable-causal-preset | 明确交付 | 是 | 不确认方向、自然邀约不超过 80 字 |
| preserve-explicit-learning-goal | 未定方案 | 否 | 保留学木工目标，600 元与两天约束 |
| chosen-pilot-simulation | 已选分支的下一轮 | 是 | 付费试讲、500 元、实际信号、失败路径 |
| multi-turn-initial-cap | 已有三项补问的下一轮 | 否 | 不重启问卷、按已知资料交付知识库方案 |
| simple-task-no-calibration | 负样本：简单事实 | 否 | 直接换算，无访谈或多视角流程 |
| plain-chat-no-calibration | 负样本：明确简短改写 | 是 | 只交付一句话 |

固定历史场景只检查给定背景下的下一轮响应，不据此声称整段对话由模型自主生成。

### 开放场景的统一答复政策

1. 每个 run 新建独立会话。开放场景最多生成三次模型回复；已选分支、明确执行和固定历史续轮只生成一次。
2. 模型问背景时，执行者只按 facts_card 回答问到的项目，不提前透露整张卡。卡片未提供的内容统一答“暂不清楚，请保留为未知，按现有信息作条件分析。”
3. 重复问题沿用既有答案，不补充内容。复合问句按独立信息项计数；一次问四项就计四项，不能只数问号。
4. 达到轮数上限后结束，不再答复。背景问题和成果同轮出现时，可答复背景问题并获取更新；交付后的可选继续菜单不算待答背景问题。
5. 只有继续菜单或空泛框架、没有可用成果时，最多回复一次固定请求：“请基于已有信息给出当前范围内可用的简短方案；未知处保持条件性，不展开其他分支。”
6. 用户要求选择深入路线时，默认只要求完成当前交付，不授权新分支。既有“已选试讲”场景沿用已给出的授权。
7. 没有背景问题、已出现请求的成果形式时结束，不按质量评分追问改进。没有问题和成果、也不属于待补救菜单/框架的回答（包括拒绝或直接改错目标），立即结束并记为有效观察。第二次仍只给菜单时结束，不反复补救直到成功。
8. 补问超过 skill 的三项上限时，仍按同一事实卡回答并记录违规，不截断问题使其看似合规。

每次保存实际用户回复原文及所用事实卡字段。答复沿用原任务语言，英文场景使用 inputs 中固定的英文事实与回复。事实卡描述的是构造的诊断环境，不能当作现实团队或商店的数据。是否停止只看问题/成果形式和轮数；是否合格由后续评审判断，不向被测模型泄露量表。

## 4. 运行隔离、证据与失败政策

### 开跑前

- 用 preregistration-template.json 登记配置、确切模型标识与版本、客户端版本、可控采样设置、系统指令及其他技能、工具权限、评审人员、顺序随机种子和时间／费用预算。不可见字段记 unknown，并说明原因。
- 保存目标四个文件的 SHA256、版本标签和可获得的仓库 revision；revision 须可解析。manifest.json 对应当前本地文件，不把未查询的远程 commit 写成已知。
- 各条件保存实际技能清单或同等证据。C0/Cs 的模型上下文不得包含目标名称、描述或正文；C1/C2 的可见性和权限须一致。
- 新会话无法清除全局预加载。不能隔离的配置无法支持无 skill 的因果比较，须换用可隔离环境，或明确改为非对照观察。
- 独立执行者只接收该条件所需内容、场景输入和实际用户回复，不得收到评分锚点、预期答案、作者评价或其他条件输出。

### 每个计划槽位

在每个“配置 × 场景 × 重复”区组内随机排列四条件，交错运行并保存顺序和随机种子；不能先跑完全部 C0 再跑 C2。每个 run 保留完整原始消息、最终回答、事件轨迹（客户端支持时）、元数据和可观察用量。

不能只向某个条件询问“列出已用技能”，这会改变任务和路由。采集依靠宿主记录或各条件一致的外部观察。

### 技术失败与有效观察

只有预先定义的提交未成功、服务错误、网络中断或客户端崩溃，才允许技术重试一次。保留原尝试、错误和可观察成本，并关联替代 run；再次技术失败则记 missing。

拒绝回答、跑偏、过长、未交付、重复确认和不必要工具调用都是有效行为观察，不得重跑挑答案。格式异常但可读时按原文评分；事件记录缺失但回答有效时，保留质量评分，调用／成本字段记 unknown。

同时报告有效输出成本和取得这些输出的全部尝试成本。预算触顶或实际模型版本变化时暂停，报告已完成槽位及原因，不得用低成本条件替换未完成条件。

## 5. 量表、适用性和人工评分

rubric.json 定义评分锚点，inputs.json 冻结各场景的适用项和最低成果要求。正向指标 1＝满足，0＝适用但不满足，NA＝输入已预定不适用。漏做要求不得记为 NA。

核心质量项：关键背景理解、有效视角、条件建议、目标与约束、证据完整性、可用交付、已选分支范围、推演可核查性。

诊断项：补问价值、冗余展开、虚构事实、初始累计信息项、视角数量、首轮和全会话字符数。冗余展开、虚构事实两项风险指标以 1 表示风险出现。

质量与证据评分只看该 run 中模型实际收到的消息、控制者回复和可审计工具结果。未发送的 facts_card 字段不算模型已知事实：未提到不扣分，猜中也不算证据。评审须核对实际发送轨迹。

补问价值为动态诊断项，不是合格交付率的必需项。未请求背景信息时记 NA；请求至少一项时，检查所有新增请求，固定历史里的问题不参与此项评分。

成果满足性按结束时明确提交的最终成果评分。没有修订说明时取最后提交的成果，不能从多版中挑最好的一版。关键背景、有效视角、条件建议和推演结构按最终判断/成果评分；目标与硬约束、证据完整性、已选分支范围及风险项则检查完整生成轨迹。前轮虚构事实、明确改错目标或未经授权扩张，末轮不再提及也仍须计入。明确标为可修正的假设随新背景更新，不自动算错误改目标。

- 四条件的任务质量要求相同。缺少 A/B 标签、固定标题、事实／推断字样或选择菜单，不自动扣分。
- 有效视角须在同一目标内提供至少两个有依据、会影响行动、评价或取舍的理解。步骤、标题、措辞变化，以及一次推演的成功和失败结果，不自动算多个视角。
- “两个视角”是默认常见形式，最多三个是 skill 在适用讨论中的边界，并非所有任务都须给出 2–3 个。分别报告质量比较和 C1/C2 协议合规情况。
- 提问按初始对齐累计索取的信息项计数，包含给定前文。已回答三项后再索取第四项即违规。“通常零问或一问”不是所有场景的硬上限。
- 依据可以是输入事实或明确标注的假设。未查得的事实不能写成已观察；无需检索的构造场景不要求额外联网。
- 试讲价格、预算分配和检验阈值属于设计参数，须明确标为提议并符合约束。指定试讲场景禁止虚构报名率，标为“假设”也不例外。
- 有限推演须说明实际可检查信号如何影响后续动作，并覆盖至少一个重要的不利或未知结果。问询人数不能作为付款或市场规模的证据。
- 明确交付在当轮可做时直接完成；开放讨论可在关键补问后、固定轮数内完成。不得靠缩短首轮、延后交付取得成本优势。

### 双人评审

两位评审独立评分，尽量至少一位不是作者。先用 calibration-examples.md 中四个作者构造的例子校准；这些例子不计入正式 run，也不是模型效果数据。

评审包提供原始任务、用户回复、输出和阶段要求，隐藏条件、模型配置、用量及运行顺序。若统一遮盖输出中的 skill 名称，须保留原始档案和遮盖规则，不改写内容或风格。作者仍可能认出自己的提示或样例，须披露这一盲法局限。

每项评分附原文位置和理由；缺失记“未找到”，并引用输入要求。保留两位原始评分后，再讨论或交第三方裁决。报告裁决前一致率、分歧数量和最终评分；一致率高也不能证明指标有效。AI 可辅助整理和定位，不能替代全部人工评分。都采用提示工程，不构成形式上的循环论证；主要风险仍是共同偏差和缺少独立验证。

## 6. 主要结果、统计口径与诊断旗标

### 主要结果

合格交付率：一个 run 的全部场景必需质量项均为 1，适用的冗余展开／虚构事实风险均为 0，才算合格。各场景必需项在 inputs.json 冻结，不得看到某条件的输出后临时增加要求。

有效视角率：只统计预设需要视角比较的场景，要求在明确目标内给出合理差异和选择依据。单独报告，避免总体交付率掩盖视角问题。

主要比较为 C2−Cs，用于检查完整 skill 的额外价值；C2−C0 和 C1−C0 为预定次要比较。C1 纳入所有有效输出，不筛选已加载的回答，以反映实际可用状态的效果。按加载状态分组仅作描述性补充。

先计算每场景、各条件三次有效运行的平均得分，再按场景等权聚合，两个配置分别报告。NA 不计入对应指标分母；应评分却因技术故障无法评分的记 missing，不能记 NA。配对比较只纳入两条件都有有效数据的场景，并列出实际次数和缺失。未满三次的区组不能用来宣称通过诊断旗标。

只报告配对差值、各场景结果和重复波动。48／192 次不算独立场景样本，本方案不默认计算具有确认性含义的显著性结论。

### Pilot 后用于定位问题的旗标

以下阈值是项目维护用的经验性诊断参数，不是经验证的科学界限，也不能证明“成熟／有效”：

| 旗标 | 完整诊断扩展中的口径 | 出现时处理 |
|---|---|---|
| D1 额外价值不足 | C2−Cs 的有效视角率差值 ≤0 | 检查简单提示是否已足够；暂不宣称完整 skill 有额外优势 |
| D2 交付受损 | C2−Cs 或 C1−C0 的合格交付差值 <0 | 优先定位阻塞交付、错误改目标和展开过度 |
| D3 协议不稳 | 每个配置的C1、C2分别计算适用上限联合合规率；初始信息项≤3且单轮最大视角数≤3，场景等权结果<80% | 查失败原因；不自动追加更严数字规则 |
| D4 成本压力 | 某配置中完整可比会话的逐场景 C2/Cs token 平均比值 >1.5 | 与收益并列报告，定位额外读取、重复和延期成本 |

原“≥30pp 或相对两倍”的可替代门槛已删除。C2 可能不如 C1 或 Cs，不能称为效果上限。D3 的 80% 和 D4 的 1.5 倍仅作为历史方案的诊断参数保留；修改时须冻结新协议，不能用新阈值追溯宣布旧数据达标。

视角数量取各次生成回复中对照数量的最大值，跨轮重复或替换失效视角不累计。D3 中，每个 run 任一适用上限超限即不合规，两项均不适用则记 NA；C1 和 C2 分母分开。提问合规计入固定历史已索取的信息项。

## 7. 加载证据、负样本与成本

### 加载与行为分开记录

- installed 和 catalog_visible 分别只说明文件就位、元数据可见。
- body_load_status：observed_loaded（可靠轨迹显示目标正文被提供或读取）、observed_not_loaded（宿主完整记录足以确认未加载）、unknown（轨迹不足）。
- 模型自述“使用 skill”另行记录，不能证明实际加载；加载正文也不保证执行正确。
- C1 正样本只用具备完整可审计记录的 run 计算可证加载率，同时报告已观测加载数、未知数及各自分母。
- C1 负样本分别报告目标正文加载记录和冗余流程率。加载后直接执行、加载后过度分析是两种结果；后者描述实际用户体验问题。
- 同时统计 C0 的目标行为出现率。不能根据条件建议或保留选择权的行为，推断 skill 已被调用。
- 记录不完整时，不作“自然触发 ≥50%、误触发 ≤20%”的通过结论，只保留目标行为和不必要流程的观察结果。

### 成本口径

逐次尝试、逐轮记录可获得的 input_tokens、output_tokens、cached_input_tokens、reasoning_tokens 和时延，附提供者对字段的定义。reasoning／cache 若属于输入或输出的子集，不得重复相加。

只有输入、输出计数定义一致，并覆盖同等完整会话时，才用 input+output 作为可观察总量。宿主提供计数时，须包括技能读取、工具结果和必要用户回复。覆盖范围无法确认时标 partial，不判断总 token 倍数。隐藏推理缺失记 unknown，不用字数换算补齐。

首轮和全会话助手字符数按 Unicode code point 计，包含 Markdown、标点、空格和换行；不能当作英文 word 数，也不能证明“一屏”或阅读时间。邀约等限长成果另按纯成果文本计数，包含标点和空格。

同时报告到首次可用结果的耗时、会话总时延、用户回复次数和要求回答的信息项数。保存每轮提交/返回时间，以及用户或控制者等待时间。模型服务时延排除人工答复等待，与端到端耗时分开报告。首次可用结果由评审定位；始终未交付则记 NA，不能将短失败当作快速完成。

预算在 preregistration 中登记；没有所选配置的实际单价时，不预估费用或承诺节省。缺少可比 token 数据时，D4 记“无法判定”。C1、C0 的成本一并展示，不能只比较 C2。

## 8. 冻结、报告、维护和停止

### 开跑顺序

1. 登记模型、客户端、预算、其他指令和技能，确认四条件可以隔离。
2. 确定两位评审，用四个独立作者示例校准。
3. 完成 preregistration，冻结 inputs、rubric、短提示、事实卡、模型设置和 SHA，导出随机顺序及匿名映射。
4. 采集 48 个 pilot 槽位，保留全部尝试、实际回复和轨迹，评分前不改量表。
5. 只检查流程能否执行、评审分歧和失败类型。需要修改时，保留旧协议并冻结新版本。
6. 在预算内运行 192 槽位诊断扩展。无法隔离或预算不足时，报告实际完成部分。
7. 按 REPORT-template.md 报告完整场景表、差值、成本、未知／缺失、裁决前一致性和失败例，引用成功与失败原文。
8. 每项结果对应版本和配置。新版本修复失败后，另跑对应回归，不覆盖原始失败。

README 只能依据实际结果写“在某版本、某配置、某构造场景集中观察到某项差值”，并保留缺失、例外和成本。不能宣称已证明普遍减少认知窄化、节省固定 token 比例、具有长期用户效果，或优于未比较的 skills。实验尚未运行时，沿用现有验证边界。

### 本轮停止条件

文档、输入、量表、模板及版本对应关系达到可交接程度、静态一致性修订完成后，即停止增加规则。真实加载率、评分结果、模型收益和成本须待实际采集，本轮不填造结果。
