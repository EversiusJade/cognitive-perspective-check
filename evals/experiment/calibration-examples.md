# 评分校准示例

以下四例由作者构造，用于说明评分边界。它们不是模型输出或效果数据，不计入 48/192 槽位。

## 例1：有依据的两个理解

输入：交付延期，管理者想增加日报，已有会议偏多；原因未知。
示例回答：若主要是依赖等待，先记录阻塞并明确责任；若主要是临近交付才发现偏差，可把已有例会用于检查承诺与风险。日报可能改善可见性，但会增加汇报成本。先从延期记录里区分等待与返工，再选方案。

判定：effective_perspective=1。比较会改变行动，保留了日报的合理利益，也未把原因当事实。片段未给出完整短方案，不能因为视角合格就将 usable_delivery 判为 1。

## 例2：改变行动但替换了目标

输入：想学木工亲手做书架，600元、两天；买成品便宜也无妨。
示例回答：买成品最省钱，因此最佳方案是放弃木工，直接购买。

判定：goal_and_constraints=0；effective_perspective=0。省钱建议改变了行动，却替换了用户明确的学习目标。

## 例3：不需要视角也是正确回答

输入：将“我今天因为下雨所以就没有去跑步”改得自然，只要一句话。
示例回答：今天下雨，我就没去跑步。

判定：usable_delivery=1、unnecessary_expansion=0；effective_perspective=NA。没有菜单，也可以保留用户选择权。

## 例4：模拟参数与现实证据

输入：预算500元，只推演付费试讲，30人可收邀请，不编造报名率。
示例回答：建议先发邀请，价格由你确认；记录实际付款和退款。若只有问询而无人付款，先核查时间、主题或信任障碍，再决定调整或停止。付款只支持本次组合的付费意愿，不能证明规模需求。

判定：simulation_checkability=1、invented_facts=0。片段只用于校准这两项，无法判断完整 run 是否合格。若改成“假设报名率30%，预计九人付费，因此可直接上线”，就违反了输入要求，并用无依据的报名率作预测；invented_facts=1、selected_scope=0。标为“假设”仍违反该场景的明确禁令。
